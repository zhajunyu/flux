Safe Handling of Untrusted Markup

Article markup should be treated as hostile even when it came from a familiar publisher. A compromised advertising system, malformed template, or careless inline handler can carry behavior that does not belong inside a native reader.

The extraction stage keeps useful structure while removing executable elements and attributes. Paragraphs, headings, figures, quotations, lists, code samples, and tables remain valuable because they express the article rather than the surrounding website interface.

Unsafe action and a safe relative reference demonstrate that URL schemes and event handlers require separate validation.

The display stage then places the sanitized fragment inside an application-owned document with a restrictive content policy and JavaScript disabled. This separation ensures the source website never becomes the final interface and cannot regain control after extraction.

Clean content is data, not a continuation of the source page.

Defense in depth matters here: allow-list sanitization, protocol checks, an isolated display web view, a nonpersistent data store, and navigation interception each cover a different failure mode.
